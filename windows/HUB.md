# 团队版中心（Windows）

**一个文件夹，双击就能用。** 不需要装 Docker、不需要装数据库、不需要装 Node。

---

## 给装机的人：怎么准备

```bash
cd app
node tools/build-hub.mjs --with-browser     # 368 MB，服务端能出画册 PDF
node tools/build-hub.mjs                    # 89 MB，画册走「打印为 PDF」
```

产物在 `windows/dist/团队版中心/`。把**整个文件夹**拷给用户即可。

打包需要一个独立安装的 Node（默认找 `C:\nodejs\node.exe`，
可用环境变量 `BUILD_NODE_EXE` 指定）以及 `postject`：

```bash
npm install --no-save postject
```

带浏览器时需要 `chrome-headless-shell`（可用 `PUPPETEER_CACHE_DIR` 指定缓存位置）。

---

## 给使用者：怎么用

1. 把文件夹解压到本地磁盘（**不要在压缩包里直接运行**）
2. 双击 **`启动.cmd`**
3. 黑窗口里会显示一个网址，形如 `http://192.168.1.5:8080`
4. **把这个网址发给销售**，他们在手机上打开就能用
5. **黑窗口不要关**，关了销售就连不上了。电脑可以锁屏，但不要关机

第一次启动会显示每个账号的初始密码，**只显示一次**，请立刻记下并当面告诉本人。
他们首次登录后会要求改密码。

---

## 销售能看到什么

| 角色 | 能看到 |
|---|---|
| 销售（如 alice） | **只有自己的订单**，看不到别人的 |
| 管理员（admin） | 全部订单 |
| 产品资料 | 所有人可看，只有管理员可改 |

这条隔离是**服务端执行**的，不是靠界面藏起来。
实测验证：alice 拉不到 bob 的单；alice 冒用 bob 名义出单会被拒。

## 数据在哪、怎么备份

数据就在这个文件夹的 `data/` 子目录里：

```
data/
├── orders.json       全部订单（含软删除的记录，可审计）
├── products.json     产品资料
├── settings.json     公司信息（画册封面用）
├── sales.json        账号（密码是加盐哈希，不是明文）
└── assets/           产品图片
```

**每周把整个 `data/` 目录复制一份到别处**（U 盘、网盘都行）。
订单是经营凭证，丢了找不回来。

换电脑：把**整个文件夹**复制过去，双击 `启动.cmd` 即可，数据跟着走。

## 让销售在外面也能用（不在同一个 WiFi）

这个中心监听的是**局域网**地址。手机要在外面（4G/5G）也能连上，
需要一个"打通网络"的工具。推荐 **Tailscale**：

1. 在中心这台电脑上装 Tailscale 并登录
2. 在每个销售的手机上也装 Tailscale，用**同一个账号**登录
3. 中心会得到一个固定的 Tailscale 地址（形如 `100.x.x.x`）
4. 把 `http://100.x.x.x:8080` 发给销售

**为什么不直接做成"公网访问"**：手机在移动网络上**没法被外部连进来**，
所以必须有一个双方都能到达的地址。公网 IP + 端口映射、或者 Tailscale
这类组网工具，二选一。这是网络的基本约束，不是本工具的限制。

## 常见问题

**问：端口 8080 被占用了怎么办？**
答：编辑 `启动.cmd`，在 `cd /d "%~dp0"` 那行下面加一行 `set PORT=8081`。

**问：黑窗口里报错了怎么办？**
答：截图发给装机的人。程序出错时不会闪退，会打印中文说明并等回车。

**问：为什么「服务端生成画册」是灰的？**
答：这个包没带浏览器（省了 280 MB）。
用「打印为 PDF」一样能出画册，手机上也行，效果相同。

**问：能和这个单机版混用吗？**
答：不能直接混用。单机版的数据在手机浏览器里，团队版的数据在中心。
需要把产品从单机版搬过来时，用单机版的「导出备份」，
再在中心的界面上手动录入（或由装机的人用 `seed` 工具导入）。

## ⚠️ 已知缺陷：Linux 容器部署的 PDF 中文字符编码

**只影响 Docker/Linux 部署，不影响本页说的 Windows 中心。**

在 Linux 容器里由 Chromium 生成的 PDF，部分汉字会被写成**康熙部首**
（`人`→`⼈`、`白`→`⽩`、`木`→`⽊`、`几`→`⼏`、`示`→`⽰`、`寸`→`⼨`）。
字形显示看起来正常，但**复制、搜索、检索全部失效**。

实测数据（同一份画册，同一套代码）：

| 环境 | 驱动 | 汉字数 | 康熙部首 | 产品名命中 |
|---|---|---|---|---|
| Windows（团队版中心） | 浏览器命令行 | 145 | **0** | 4/5 |
| Linux 容器 | puppeteer | 124 | 25 | 0/5 |
| Linux 容器 | 浏览器命令行 | — | 有 | 0/5 |

排除过的原因：不是字体选择（试了 5 种）、不是 puppeteer、不是启动参数。
判断是 Chromium 在 Linux 上生成 PDF 的问题。

**规避方式**：用「打印为 PDF」——它用销售自己设备上的浏览器与字体，
不受影响，而且那本来就是推荐路径。
