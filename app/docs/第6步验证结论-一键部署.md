## 1. 交付了什么

**对装机的人来说只有四步**：改配置 → `docker compose up -d` → 取初始密码 → 打开网址。

建库、建应用账号、写权限文档、装中文字体、配 HTTPS **全部自动完成**。

```
docker compose up -d
```

### 三个容器

| 容器 | 作用 | 对外端口 |
|---|---|---|
| `fs-couchdb` | 订单的权威副本 | **不暴露**，仅 Docker 内网 |
| `fs-app` | 服务端 + 界面 + 同步代理（授权执行点） | **不暴露**，仅内网 |
| `fs-caddy` | HTTPS 反向代理，自动管理证书 | 80 / 443 |

**只有 Caddy 对外**，应用与数据库都在内网，减少暴露面。

## 3. 🔴 过程中挖出的四个真 bug

### 3.1 `_users` 库不存在，应用账号建不出来

全新 CouchDB 容器里**只有我们自建的 `orders` 库**，`_users` 并不自动存在。
于是写账号返回 404，日志里只留下一行：

```
创建应用账号 app：HTTP 404
```

不显眼，但账号确实没建出来。

**修复**：初始化时先 `PUT /_users`（已存在返回 412，属正常），
并且**对失败不再沉默**——非预期状态会打成 `⚠️` 带响应体输出。

> 教训：**"HTTP 404"这种看似无害的日志，背后可能是功能没生效。**
> 凡是初始化步骤，失败必须显眼。

### 3.2 HTTP→HTTPS 跳转丢端口，用户会看到"无法连接"

HTTPS 映射到 8443 时，Caddy 的自动跳转把请求送到
`https://<主机>/`（即 443），而那里没有服务。

**修复**：显式写一条跳转规则并带上 `HTTPS_PORT`。

```
修复前：HTTP 308 -> https://localhost/          ← 443，连不上
修复后：HTTP 301 -> https://localhost:8443/     ← 正确
```

> 标准 443 部署时不需要这条规则，文档里已注明。

### 3.3 镜像里的示例素材被数据卷"盖住"看不见

为了让容器里第一次打开就有带图的示例产品，我把素材 COPY 进了
`/srv/app/data/sample-assets`——**结果一张也读不到**。

原因：`data/` 被数据卷挂载覆盖，**镜像里放在那个目录的文件运行时不可见**。

**修复**：素材移到 `/srv/app/assets/`（只读的代码资产，不被挂载）。

> 教训：**被挂载覆盖的目录里不要放镜像资产。**
> 这个失败很隐蔽——文件"存在"（构建时确实 COPY 了），但运行时读不到。

### 3.4 验证脚本硬编码了开发目录布局

`verify-real-couchdb.mjs` 写死了从 `../sync/node_modules` 加载 pouchdb，
容器里没有那个路径，报 `requireStack: /srv/sync/package.json`。

**修复**：改为按顺序尝试多个位置（容器 `app/node_modules` → 本机 `sync/node_modules`），
都失败时给出**可执行的修复提示**（`cd app && npm install pouchdb`）。

## 4. 部署形态的几个设计决定

### 4.1 中文字体固定在镜像里

`fonts-noto-cjk` 装进镜像，不依赖宿主系统字体。

理由：缺字体的机器上，**画册会静默变成乱码**——
与 `pdf-catalog-generator` 是同一类失败模式（见主文档 §7.1）。
这类失败不会报错，只会产出废品。

### 4.2 用系统 chromium 而不是 puppeteer 自下载

镜像里 `apt install chromium`，并用
`PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium` 指过去，同时
`PUPPETEER_SKIP_DOWNLOAD=1` 阻止 puppeteer 自己下。

好处：镜像构建可复现、不依赖外网下载、体积更可控。

### 4.3 启动自检失败要明确报错，不静默降级

`app/server/startup.mjs` 会等 CouchDB 就绪（最多 30 次 × 2 秒），
然后建库、建账号、写设计文档。

**失败则退出进程**——同步不可用却装作可用，比直接失败更危险：
销售会以为单子存上了，其实没有。

### 4.4 应用本体零 npm 依赖

镜像里只装两个**可选**依赖：`puppeteer-core`（出画册 PDF）与
`pouchdb`（仅验证脚本用）。服务端运行本身零依赖，
所以即使这两个装失败，应用照常可用（出 PDF 那条路会明确提示）。
