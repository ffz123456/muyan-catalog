## 4. 实现要点

### 4.1 `sales_id` 的值必须是登录名（现在就要定）

因为第 4 步要接进 CouchDB 的 `validate_doc_update`，那里要求
`newDoc.sales_id === userCtx.name`。所以**现在存进订单的值必须就是登录名**，
否则接同步时要迁移全量历史数据。

当前用本地身份（`app/server/sales.mjs`），第 4 步换成真正的认证，
但**存储层的字段名与取值规则不变**。

### 4.2 `list_price` 由服务端填，不接受客户端传值

否则客户端可以伪造原价来伪造折扣，审计就失去意义。
实测：客户端传 `list_price: 1`，服务端仍写入真实的 4380。

### 4.3 写入串行化

Node 是单线程，但 `await` 之间会交错。两个并发的"读-改-写"会互相覆盖，直接丢单。
`orders.mjs` 用 promise 链把写操作串行化，实测 12 个并发出单全部落盘。

### 4.4 按月分文件存储

单文件不会无限增长，也便于按时间归档。存储接口做了封装，
将来换成 PouchDB/CouchDB 时上层不用改。

### 4.5 删除必须是软删除

硬删除在 CouchDB 上会让过滤函数拿不到业务字段，删除变更被丢弃，
客户端留幽灵订单（见 [第 1 步结论 §10.2](../../sync/docs/第1步验证结论-过滤同步.md)）。
所以 `deleteOrder()` 只改 `status` 并追加修订。

## 5. 过程中发现的两个问题

### 5.1 🔴 界面显示名与 `sales_id` 不一致（已记录，待优化）

右上角显示的是**显示名**（如「销售 A」），但订单里存的 `sales_id` 是登录名（`alice`）。
管理者在"看全部"时会看到 `alice` 这样的英文名，而界面其他地方显示「销售 A」，
**两者对不上会让人困惑**。

**建议改法**：订单列表里的归属显示走显示名映射（`alice` → 「销售 A」），
或在设置页把登录名与显示名并排展示。

### 5.2 测试脚本自身的两个陷阱（已修，值得记录）

**① `dispatchEvent` 前必须先设 value**

```js
// ✗ 错误：事件处理读到的还是旧值
await input.type('1000');
await page.$eval(sel, el => el.dispatchEvent(new Event('input')));

// ✓ 正确：先设值再派发
await page.evaluate(() => {
  const el = document.querySelector(sel);
  el.value = '1000';
  el.dispatchEvent(new Event('input', { bubbles: true }));
});
```

**② 对「动态重绘出来的元素」用坐标点击会超时**

切换使用人时，弹层列表每次都会重新渲染，页面处于重排中，
Puppeteer 的 `page.click()` 会一直等元素位置稳定而报
`Waiting failed: 10000ms exceeded`。

**实测对比**：

| 方式 | 结果 |
|---|---|
| `page.click('#whoList .item:nth-child(2)')` | ✗ 超时 |
| `page.evaluate(() => el.click())` | ✓ 正常触发接口调用 |

**结论**：验证**动态重绘**的元素时，一律用页面内派发 `el.click()`，
不要用坐标点击。这不是应用缺陷，是测试方法的限制。

> 该现象已记入 [主文档 §17.1c](../../docs/项目主文档.md) 的界面实现经验。

## 6. 产物与复现

```
app/
├── server/
│   ├── orders.mjs     订单：不可变 + 追加修订 + 软删除 + 并发串行化
│   ├── sales.mjs      销售人员与当前身份（第 4 步接认证的预留接口）
│   ├── store.mjs      产品与设置存储
│   ├── couch.mjs      CouchDB 客户端 + 过滤函数 + 校验函数
│   ├── index.mjs      HTTP 服务（零依赖）
│   └── render-catalog.mjs  画册渲染 + 分页断言 + PDF
├── public/            界面（开单优先，手机优先）
└── tools/
    ├── verify-orders.mjs        模块验证（45 项）
    ├── verify-real-couchdb.mjs  同步验证（22 项）
    ├── ui-screenshot.mjs        界面验证（40 项）
    └── assert-lib.mjs           断言库
```

复现：

```powershell
cd app
node tools/verify-orders.mjs                        # 模块验证
node --env-file=.env tools/verify-real-couchdb.mjs   # 同步验证
node server/index.mjs                                # 启动，另开终端跑界面验证
node tools/ui-screenshot.mjs
```

> ⚠️ `verify-orders.mjs` 会**清空订单数据**后重建，不要在正式数据上运行。
