# 账号管理验证结论（开源发布前置）

> **定位**：本项目要**开源给任意经销商自己部署**。
> 部署的人不会改代码，也不会去编辑数据文件——如果界面上加不了人，
> 这套东西对他们就是不可用的。
>
> 验证日期：本次会话 · 结果：**51 / 51 通过**

---

## 1. 这一步补的是什么缺口

在此之前，账号是**写死在代码里**的三个（admin / alice / bob）：

```js
const BUILTIN_SALES = [
  { name: 'admin', display: '管理者', admin: true },
  { name: 'alice', display: '销售 A' },
  { name: 'bob',   display: '销售 B' },
];
```

对"自己公司内部用"还凑合，但**开源给别人部署就不成立了**：
别人公司里没有 alice 和 bob，他们需要建自己的人。

更糟的是：**忘了密码只能删掉整个 `sales.json`**，
那会把**所有账号**一起重置——对真实用户是不可接受的。

---

## 2. 做了什么

### 2.1 管理员可在界面上管理账号

设置页 →「销售人员账号」→ 每一项可点开编辑。

| 操作 | 说明 |
|---|---|
| **新建账号** | 填登录名、姓名、邮箱、手机号；可选"管理员"身份 |
| **编辑** | 改姓名 / 邮箱 / 手机号 / 管理员身份 / 启用状态 |
| **重置密码** | 生成临时密码，当场显示一次，强制改密 |
| **停用** | 离职人员用这个：**不能登录，但订单全部保留** |
| **删除** | 真删账号；**名下订单不删**（订单是经营凭证） |

### 2.2 一次性密码必须当场记下

新建账号、重置密码都会返回一串随机密码。**库里只存哈希，关掉窗口就再也查不出来。**

所以界面上专门做了一个显眼的展示框（粗体大字 + 警示色边框 + 可一键全选），
文案明确写"请当场记下或直接念给本人"。

> 这不是装饰。做得不显眼，管理员会顺手关掉，然后对方就登不进来了，
> 而管理员也不知道该给什么密码。

### 2.3 首次登录强制改密

新建的账号、被重置密码的账号，`must_change_password = true`，
登录后立即弹出改密窗口。

**实测确认**：新建账号 → 登录 → 改密 → 标记消除；重置后旧密码立即失效、临时密码可用、再次要求改密。

### 2.4 邮箱字段（仅作联系记录）

| 谁 | 能看到 |
|---|---|
| 未登录 | 只有登录名 + 姓名（登录页需要） |
| 销售 | 同上，看不到同事的联系方式 |
| 管理员 | 完整资料（姓名、邮箱、身份、状态） |

> ⚠️ 未登录视图是**白名单式构造**的，不是"删字段"。
> 将来给账号加字段也不会意外泄露。

**账号上刻意没有手机号字段**：密码找回走"管理员重置"，
不做短信验证码（需要短信网关与企业资质，自部署场景不现实）。
留一个用不上的字段只会让人困惑"这要填吗"。

> 注：订单上的**客户电话**（`customer_phone`）是另一回事——那是订单内容，保留。

## 3. 🔴 一条安全约束：不能弄丢最后一个管理员

如果唯一的 admin 把自己降级成普通销售，**就再也没人能管理账号了**——
而且没有任何界面能救回来，只能手工改数据文件。

所以服务端强制：

```
降级最后一个管理员  → 400「这是最后一个可用的管理员，不能停用或降级——否则没人能再管理账号」
停用最后一个管理员  → 400
删除最后一个管理员  → 400
```

这条约束**必须在服务端**，不能只靠界面把按钮藏起来。

## 5. 过程中的三个判断错误（都是我自己写错的断言）

记录下来，因为这三个都**看起来像功能缺陷，实际是测试写错了**：

| 现象 | 真实原因 |
|---|---|
| 「新账号看不到任何既有订单」失败 | 那条是 `product:p1`——**共享的产品文档，本来就该所有销售可见**。断言没有区分订单与产品 |
| 「未登录拿不到管理员标记」失败 | 判据写了 `"admin"` 子串，而**管理员的登录名本身就叫 admin**。应判 `"admin":` |
| 「管理员能看到完整资料」失败 | 断言 `'email' in x`，但内置账号从没填过邮箱，那字段是 null。应**建一个带邮箱的账号再验证** |

> 教训：涉及"权限该不该看到"的断言，判据必须精确到**字段名**，
> 而且**要构造一个真的含该数据的样本**，不能靠既有数据碰运气。

## 6. 同时挖出的一个真 bug

**新建账号后弹层不关，列表点不动。**

点「我已记下」只隐藏了密码框，整个弹层还盖在列表上。
管理员想接着看刚建好的账号、或再建一个时，**点列表没反应**，会以为界面卡住了。

已修复：点「我已记下」时连弹层一起关掉。

> 这类"操作完成后界面没有回到可用状态"的问题，只有真的走一遍完整流程才会发现。

## 7. 密码找回：已定方案 = 管理员重置

**已实现并通过实测**：管理员在账号页点「重置密码」，
系统生成临时密码当场显示一次，对方登录后强制改密，旧密码立即失效。

**明确不做自助找回**（这是与项目所有者确认后的决定）：

- **不做短信验证码**——需要短信网关与企业资质，自部署场景不现实
- **不做邮件自助重置**——这套系统部署在经销商自己的局域网里，
  不一定能连外网，更不一定有邮件服务器；
  实现成"必须配好 SMTP 才能用"，大多数部署根本用不上
- **不做备用码**——管理员点一下就能重置，小团队里这是最省事的路径

> 规模判断：一家经销商公司通常几个到几十个销售，
> 忘密码是低频事件（每人一年几次），管理员顺手点一下就解决。
> 为这种频率的诉求引入邮件服务器或短信网关，是明显不划算的复杂度。

如果将来规模变大（比如上百人、多门店），再考虑备用码方案——
它不依赖任何外部服务，是这里最合理的自助方案。
