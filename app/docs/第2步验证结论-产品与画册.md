## 3. 🔴 目视检查抓到的严重 bug（已修）

### 3.1 隐藏的编辑弹层覆盖全屏，吃掉所有点击

**这是本次最有价值的发现，而接口自检全绿是发现不了的。**

现象：截图脚本报告 8 张图都生成了，但 4 张手机截图哈希**完全相同**。

诊断结果：

```
catalogRect: { x:137, y:44, w:117, h:44 }
elementAtCenter: "DIV.sheet"        ← 标签按钮的中心点是弹层，不是按钮本身
```

**根因**：CSS 里 `.sheet { display: flex }` **压过了 `[hidden]` 属性的默认 `display: none`**。
于是那个"隐藏"的编辑弹层始终铺满全屏（透明遮罩），拦截了页面上所有点击。

**影响**：这不是截图问题，是**真人使用时页面完全点不动**——
标签切不了、产品点不开、按钮按不了。整个界面等于不可用。

**修复**（`public/style.css`）：

```css
/* display 属性会压过 [hidden] 的默认 display:none。
   本文件里 .sheet / .toast / .photo-preview 等都设了 display，
   若不强制，隐藏的编辑弹层会继续覆盖全屏并吃掉所有点击。 */
[hidden] { display: none !important; }
```

**教训**：给元素设了 `display` 的元素，用 `hidden` 属性隐藏是**无效的**。
凡是靠 `hidden` 控制显隐的元素，样式里都必须有 `[hidden] { display:none }` 兜底。

### 3.2 截图脚本本身的缺陷（已修）

第一版截图脚本只是"点一下、截一张"，**点击没生效也不报错**，于是静默产出了 4 张相同的废图。
如果我没去比对哈希，就会拿着一叠废图宣称"界面验证通过"。

**已加两道防线**：

1. 每个交互后**断言状态真的变了**（如 `activeTab === 'catalog'`），不成立即报错退出
2. 截图前等一次**实际重绘**（CSS 动画哨兵），避免截到旧帧

## 4. 一个被误判为 bug 的现象（记录以免重复排查）

画册选择页的截图里，底部操作条看起来挤在内容中间。
量测后确认**是正常布局**：

```json
{ "position": "fixed", "rect": { "y": 751, "h": 93 }, "viewportH": 844,
  "containingBlockAncestor": null }
```

`751 + 93 = 844` 正好等于视口高度，即**确实贴在视口底部**；
且没有 `transform` / `filter` / `contain` 祖先破坏 `position: fixed` 的包含块。
截图尺寸也确认是视口大小（780×1688 = 390×844 @2x），不是全页截图。

**结论**：是目视误判，非缺陷。量测工具保留在 `app/tools/probe-actionbar.mjs`。

## 5. 实现要点

### 5.1 单进程、零外部依赖（符合 §2b.5）

服务端只用了 Node 内置模块（`http` / `fs` / `path` / `crypto`），**没有引入任何 npm 依赖**。
这样后续要把同步代理挂进来时，不用为一个独立服务再写一套配置。

### 5.2 图片必须前端压缩

手机原图常 5–10MB，直接上传会让人等到以为卡死。
前端用 canvas 压到长边 1600px / 质量 0.82 再上传，实测 5 张示例图落到 7–14KB。

> 转 JPEG 时先铺白底：否则透明 PNG 会变成黑块。

### 5.3 画册必须自包含

本地图片一律转成 base64 data URI 内联进 HTML。
这样生成的 PDF 发给客户后**不依赖网络、也不依赖服务器还活着**。

### 5.4 两种出 PDF 方式（对"不想学"的用户很重要）

| 方式 | 前提 | 适用 |
|---|---|---|
| **浏览器打印为 PDF** | 什么都不用装 | ✅ 默认推荐，手机上也能用 |
| 服务端生成 PDF | 需装 puppeteer | 后续 Docker 镜像自带，一键出文件 |

服务端那条路走 **CDP `Page.printToPDF` 直写文件**——
`page.pdf()` 的流式回传在当前环境会报 `Protocol error (IO.read)`，实测不可用。

## 6. 产物与复现

```
app/
├── server/
│   ├── index.mjs            HTTP 服务（零依赖）
│   ├── store.mjs            JSON 存储 + 原子写入
│   └── render-catalog.mjs   画册渲染 + 分页断言 + PDF
├── public/                  界面（零依赖，手机优先）
│   ├── index.html
│   ├── style.css
│   └── app.js
├── tools/
│   ├── seed-sample-data.mjs 导入示例产品
│   ├── ui-screenshot.mjs    界面验证（带状态断言）
│   └── probe-actionbar.mjs  布局量测
└── data/                    产品数据、图片、导出、截图
```

复现：

```powershell
cd app
node tools/seed-sample-data.mjs     # 导入 5 款示例产品
node server/index.mjs               # 启动，打开 http://127.0.0.1:8080
node tools/ui-screenshot.mjs        # 另开终端：界面断言 + 截图
```

> 截图脚本复用 `catalog/` 下已装的 puppeteer，不需要在 `app/` 再下一份 Chromium。
