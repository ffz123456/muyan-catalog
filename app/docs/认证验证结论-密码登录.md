## 1. 这一步补的是什么漏洞

在此之前登录是**"选个名字即进入"**：

```
打开页面 → 点「销售 A」→ 就是销售 A 了
```

**任何人都能选别人的名字开单、看别人的订单报价。**
而订单正是按这个名字隔离的——**隔离可以被绕过，等于没有隔离。**

报价与客户是销售各自的业务资源，这个漏洞让"销售之间互相不可见"
这个核心卖点形同虚设。

---

## 2. 做了什么

| 项 | 说明 |
|---|---|
| 密码存储 | Node 内置 `scrypt` 哈希（N=16384, r=8, p=1），每账号独立随机盐；**不存明文** |
| 密码校验 | `crypto.timingSafeEqual` 恒定时间比较，避免逐字符试探 |
| 登录 | 账号 + 密码；成功后下发 `HttpOnly` 会话 Cookie（30 天） |
| 失败话术 | **统一为"账号或密码不正确"**，不区分账号是否存在（防账号枚举） |
| 初始密码 | 首次运行随机生成，**只在服务端启动日志打印一次** |
| 强制改密 | 首次登录（或管理员重置后）要求立即修改 |
| 改密 | 需验证旧密码；新密码至少 6 位、不能与原密码相同 |
| **移除后门** | 删掉 `POST /api/sales/current`——它原本允许**无需密码就变成任何人** |

## 4. 顺带修掉的两个真 bug

### 4.1 🔴 账号初始化竞态，导致打印出来的初始密码是错的

首次运行时日志里每个账号出现了**两个密码**：

```
admin    mp9erw9nau      ← 无效
alice    g8p6933pub      ← 无效
bob      mpusccguhh      ← 无效
admin    kfyb2ajkr9      ← 实际生效的是这组
alice    qcqnq5p2yu
bob      hpus3tn6mb
```

**原因**：`bootstrap()` 里 `Promise.all` 并发取"账号列表"和"当前账号"，
两者都触发 `listSales()`；文件还不存在时**两个调用各自执行了一遍初始化**，
后写的覆盖先写的。

**危险之处**：打印出来的第一组密码是无效的，
照着它登录会失败且不知道原因——**用户会以为系统坏了**。

**修复**：用单一 promise 串行化初始化，保证只跑一次。

### 4.2 🔴 一个非关键文件损坏，导致整个服务起不来

```
初始化失败：数据文件损坏：current-sales.json
Unexpected token ' ', "        "... is not valid JSON
```

`current-sales.json` 只是"记住上次用谁"的便利文件，却在一次写入
被打断后变成了一片空格（58 个空格），**结果整个服务启动失败**。

**修复**：三个存储模块（`sales.mjs` / `store.mjs` / `orders.mjs`）的读取
全部改为**损坏时备份证据 + 警告 + 当作缺失继续**，
原始内容留在 `.corrupt-<时间戳>` 里供人工检查。

**权衡说明**：订单是经营凭证，绝不能静默丢数据——所以**一定要备份**，
但不该让一个文件损坏拖垮整个系统。选择是"服务继续可用 + 保留全部证据"。

实测验证：修复后重启，服务正常启动并输出

```
[数据] current-sales.json 内容损坏，已备份为 current-sales.json.corrupt-1791827033506 并重建。
```

## 5. 开发模式免密入口（仅本机）

认证上线后，每个验证脚本都要带密码才能切换身份，
而**把密码硬编码进脚本本身就是坏习惯**。

所以加了一个显式开关：

```
DEV_ALLOW_PASSWORDLESS_LOGIN=1
```

- **默认关闭**
- 只在服务绑定回环地址（`127.0.0.1` / `localhost` / `::1`）时生效，否则自动忽略并告警
- 请求体需显式带 `devNoPassword: true`
- **不是产品功能，不要写进部署文档**

验证脚本优先走它；若不可用则回退到读环境变量里的密码。

## 6. 安全边界（说清楚它保护什么、不保护什么）

**保护**：
- 销售之间无法互相冒充 → 报价与客户互不可见这个核心卖点成立
- 未登录无法访问同步端点
- 账号列表不泄露密码哈希

**未保护**（本版本的已知边界）：

| 项 | 说明 |
|---|---|
| **传输未加密** | 当前是 HTTP，密码明文过网。**部署到局域网前必须配 HTTPS**（主文档 §2b.5 第 4 条） |
| 会话 Cookie 未设 Secure | 因为没有 HTTPS；配好 HTTPS 后应开启 |
| 无登录失败次数限制 | 可被暴力破解；生产建议加退避或锁定 |
| 无"管理员重置他人密码"功能 | 忘了密码只能删 `data/sales.json` 重新初始化（会重置所有账号） |
| 无自助注册 | 账号写死在 `BUILTIN_SALES`，增删账号需改代码或直接编辑数据文件 |

> 这几项已登入主文档技术债务登记，不是遗漏。

## 7. 密码恢复说明（写给人看的）

**密码是哈希存储的，无法找回，只能重置。**

- 销售忘了密码 → 管理员需要重置（当前版本需删 `data/sales.json`，会重置所有账号，
  **慎用**；建议改数据文件里的单个账号）
- 所有人忘了密码 → 删掉 `app/data/sales.json`，重启服务，
  新密码会重新打印在启动日志里

> 销售账号的增删与重置目前不够友好，是下一步该补的管理功能。
