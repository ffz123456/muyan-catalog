# Windows 部署

这个项目在 Windows 上有 **两条路**，按你的情况选：

| 你的情况 | 走哪条 | 一键程度 |
|---|---|---|
| **本机已装 Docker Desktop** | [一、一键启动（推荐）](#一一键启动docker-路线) | ⭐ 双击即可，**已完整实测** |
| 不想装 Docker | [二、绿色便携版](#二绿色便携版未完成) | ⚠️ **未完成**，见下文说明 |

> 为什么推荐 Docker：它已经在本机**完整跑通过**——装、用、验证、卸载都试过。
> 绿色便携版我试了，卡在一个还没查清的问题上（见第二节）。
> 我不想把没验证过的东西当成品给你。

## 一、一键启动（Docker 路线）

### 前提

装 [Docker Desktop](https://www.docker.com/products/docker-desktop/) 并启动它。
装一次，以后不用管。

### 用法

```
双击  deploy\一键启动.bat
```

就这样。脚本会自动：

1. 检查 Docker 装了没、在不在运行（没装会告诉你去哪下）
2. 生成配置（**随机数据库密码**，不用你自己想）
3. 启动三个容器（数据库 / 应用 / HTTPS）
4. 等就绪后**打开浏览器**
5. 把初始登录密码打印出来，并存到 `deploy\初始密码.txt`
6. 导出根证书到 `deploy\caddy-root.crt`

**停止服务**：双击 `deploy\一键停止.bat`（数据不会丢）。

### 装完会看到什么

```
可以使用了：  https://192.168.1.11:8443/

· 自己用：把上面的网址复制到浏览器
· 同事用：把同一个网址发给他们（同一局域网内）

· 浏览器会提示「证书不受信任」——这是正常的：
    本机自己签的证书，不是从证书机构买的。
    点「高级」→「继续前往」就能用。
```

**关于证书警告**：这个警告可以彻底去掉。双击 `deploy\caddy-root.crt` →
安装证书 → 本地计算机 → 受信任的根证书颁发机构。装完就不再提示了。

> 这一步需要管理员权限（装证书到"本地计算机"）。不想装也行，
> 每台设备第一次访问点一下「继续」而已。

### 三个容器分别是什么

| 容器 | 作用 | 对外端口 |
|---|---|---|
| `fs-couchdb` | 订单的权威副本 | **不暴露** |
| `fs-app` | 服务端 + 界面 + 同步代理 | **不暴露** |
| `fs-caddy` | HTTPS 反向代理 | 8080 / 8443 |

只有 Caddy 对外。数据库和应用都在 Docker 内网，外面连不上。

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| 提示「没有找到 Docker」 | 装 Docker Desktop，装完重启一次 |
| 提示「Docker 服务没在运行」 | 启动 Docker Desktop，等托盘图标稳定 |
| 网址打不开 | 等 1-2 分钟（第一次要构建镜像）。还不行看 `docker compose logs app` |
| 想换端口 | 改 `deploy\.env` 里的 `HTTP_PORT` / `HTTPS_PORT`，再重跑一键启动 |
| 忘了登录密码 | 管理员在「设置」页能重置他人的。自己的忘了见下 |
| 所有密码都忘了 | 删掉 `app-data` 卷重建：`docker compose down -v`（**会清空产品和账号**） |

## 二、绿色便携版（未完成）

### 目标是什么

**解压 → 双击 → 就能用。不装 Docker、不要管理员权限。**

这需要把 Node 运行时、CouchDB、Chromium 都打进一个包。我把组件都准备好了，
也验证了关键部分，但**打包这一环没走通**。

### 已经验证通过的部分

| 组件 | 结果 |
|---|---|
| Node 24 便携运行时 | ✅ 下载、解压、运行都正常（36 MB 压缩 / 102 MB 解压） |
| Chromium headless shell | ✅ 能正确产出**中文** PDF（嵌了 MicrosoftYaHei，5/5 产品名可提取） |
| CouchDB 便携启动 | ✅ 能以普通进程启动（`bin\couchdb.cmd` 直接调 `erl`，不需要装服务） |
| CouchDB 管理员配置 | ✅ 摸清了格式，能自己生成 `-pbkdf2:sha256-...` 哈希写进配置 |

### 卡在哪里

复制一份 CouchDB 到普通目录、以普通用户身份启动，**Erlang 的 `os_mon`
端口程序起不来**：

```
[os_mon] win32 supervisor port (win32sysinfo): Erlang has closed
→ pubkey_os_cacerts:load_win32/0 失败
→ couch_replicator 启动失败
→ 整个 CouchDB 拒绝启动
```

排查到的事实：

- 本机**服务版** CouchDB（以 LocalSystem 身份跑）**完全正常**
- 已排除：端口冲突（换了 15984）、Erlang 节点名冲突（改成 `couchdb_portable`）、
  目录污染（换全新目录一样）、沙箱限制子进程（Node 起管道子进程正常）
- 已确认：CouchDB 3.x **移除了 Admin Party**，没有管理员账号会直接拒绝启动
  （这一条已解决：启动前把账号写进配置即可）

**没查到底。** 可能在干净的 Windows 机器上就正常（本机装了服务版 CouchDB，
可能有环境干扰），也可能 CouchDB 的 Windows 发行版就是不适合便携运行。

### 想继续推进的话

如果你有一台**没装过 CouchDB** 的 Windows，把
[Apache CouchDB 3.5.3 的 Windows 安装包](https://couchdb.apache.org/)装到普通目录，
按上面"已验证"的方式配好管理员和端口，看能不能起来。能起来就说明是环境干扰，
便携版可行；起不来就说明这条路要换方案（比如改用 SQLite 之类无守护进程的存储）。

## 三、为什么不干脆只做便携版

诚实说明取舍：

- **Docker 路线**：用户要先装 Docker Desktop（约 1 GB），但装完体验最稳，
  而且**我能完整验证**——本机就是这么跑的
- **便携路线**：用户什么都不用装，但需要我把 CouchDB 的 Windows 便携运行
  彻底调通，而这一步**我没做成**

在这个前提下，给你一个验证过的方案，比给你一个"理论上更好但没人试过"的方案更负责。

## 四、两条路的关系

它们用的是**同一套代码、同一个镜像、同一个编排文件**。

```
deploy/
├── 一键启动.bat          ← Docker 路线：双击这个
├── 一键停止.bat
├── 一键启动.ps1           （被 .bat 调用，也可单独运行）
├── docker-compose.yml    三容器编排
├── Dockerfile            应用镜像（含 Chromium 与中文字体）
├── Caddyfile             HTTPS 与证书
├── .env.example          配置模板
├── README.md             通用部署指南
└── WINDOWS.md            本文件

windows/                  ← 便携路线的打包脚手架（未完成）
├── cache/                下载的组件（不入库）
├── template/             启动器模板
└── tools/                打包与验证脚本
```

便携版一旦调通，它会复用 `deploy/` 里的应用代码与 Caddy 配置，
只是把 CouchDB 与 HTTPS 换成免安装的形态。
